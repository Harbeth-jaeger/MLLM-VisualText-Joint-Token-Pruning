# 项目进展

> 更新时间：2026-10-17

## 1. 项目在做什么

这个项目主要研究多模态大模型的 token pruning。简单来说，就是在模型回答问题前，删掉一部分不重要的文本和视觉 token，希望在尽量不影响回答效果的情况下，减少计算量并加快推理。

目前使用 Qwen2.5-VL-7B-Instruct，在 MileBench 的 MMCoQA 数据上开展实验。MMCoQA 的输入通常包含较长的文本、多张图片和一个问题，比较适合观察不同模态的信息应该如何保留。

当前的基本技术路线是：先把可剪枝内容分成文本 chunk 和视觉 chunk，再根据问题为每个 chunk 计算重要性，最后让两种模态在同一个总预算下共同竞争。若文本和视觉候选 token 数分别为 $N_t$ 和 $N_v$，保留率为 $\rho$，则总预算为：

$$
B=\left\lfloor\rho(N_t+N_v)\right\rfloor.
$$

算法根据 chunk 分数决定文本和视觉各保留多少，并在 chunk 内进一步选择 token。被保留的视觉 token 仍使用 Qwen 原来的特征和位置编码，因此剪枝只改变输入数量，不改变模型结构。整体流程可以概括为：

```text
问题 + 文本 + 图片
        ↓
文本/视觉分块与重要性评分
        ↓
在统一预算 B 下选择 token
        ↓
保留原始特征和位置，送入 Qwen 生成答案
```

## 2. 已经完成的工作

前期已经完成两轮探索实验，并搭建了较完整的实验流程，包括数据处理、模型推理、token 剪枝、多卡运行和结果评测。

实验 001 主要验证文本 token pruning 能否正常工作。它属于早期探索，相关实验记录仍然保留，但旧代码已经移除。

实验 002 开始同时剪枝文本和视觉 token，并尝试根据问题内容动态决定两种模态各保留多少。实验表明：

- 在较温和的剪枝比例下，模型效果可以基本保持，说明联合剪枝这条路线值得继续研究；
- 当前动态分配方法没有稳定优于随机或固定分配，说明原来的 token 评分方法还不够可靠；
- 文本和视觉特征虽然维度相同，但分数并不能直接比较，导致算法明显偏向保留文本；
- 原有评测器对 `4` 和 `four` 这类等价答案处理得不够好，后续会同时保留原指标和更鲁棒的评测结果；
- 只剪视觉 token 的对照在部分样本上无法满足相同总预算，因此不再作为后续实验的主要对照。

## 3. 当前准备解决的问题

当前优先推进实验 004，直接学习文本和视觉 chunk 对标准答案的边际 utility。原计划先运行实验 003，现调整为先验证 learned utility；实验 003 后续作为独立对照、chunk 内 token 选择辅助方法和可选 scorer 特征。

实验 004 使用冻结 Qwen 的 leave-one-chunk-out gold-answer NLL 变化生成标签，只训练轻量 scorer。在线推理不使用标准答案或反事实删除，只提取冻结 Qwen 特征并一次性预测所有 chunk utility。

首版使用 group-aware 的 120/30/50 train/validation/test 划分，固定 50 样本仍只用于最终评价。文本与视觉使用分模态输入投影和共享 utility head，在同一个严格 token 预算下直接竞争。

这样设计仍保持 Qwen 本身不变，只调整“哪些 chunk/token 应该被保留”的判断方式；如果新方法有效，改进可归因于更贴近答案目标的选择信号。

## 4. 当前路线：Learned Scorer

实验 003 主要解决“文本和视觉分数能否公平比较”，但语义相关不一定等于对回答真正有用。例如，一个片段可能与问题主题相关，却没有提供答案；多个片段也可能表达重复信息。

因此，实验 004 计划训练一个轻量级 utility scorer，直接预测每个文本或视觉 chunk 对最终回答的贡献。训练标签由冻结的 Qwen 产生：分别比较完整输入和删除某个 chunk 后，模型对标准答案的损失变化：

$$
u_g=\ell(X\setminus g,y)-\ell(X,y).
$$

其中 $u_g$ 越大，说明删除 chunk $g$ 后模型越难得到正确答案，这个 chunk 就越应该保留。scorer 会同时接收文本和视觉 chunk 的特征，并输出同一标度下的 utility 分数，再用于统一预算下的排序和剪枝。

这条路线比实验 003 更直接地对齐最终目标，但也需要额外生成训练标签和训练 scorer，成本更高。当前已经决定先运行实验 004；实验 003 保留为后续辅助方法与对照，不再作为实验 004 的前置条件。

## 5. 当前进度和阻塞

实验 004 的首版代码已完成，包括 group-aware split、teacher-forced utility 标签、缓存特征、pairwise+Huber scorer 训练、严格联合预算 planner、多卡分片入口和结果汇总。

目前完成了纯算法回归测试和真实 GPU 端到端 smoke：FlashAttention 2 已实际启用；优化后的 $4\times4$ 视觉 utility chunk 在两个样本上分别产生 176/153 个 chunk，耗时 49.1/34.5 秒，峰值显存 18.49/17.91GB。1 个 train、1 个 validation 的 scorer smoke 可以反向传播、保存并重新加载 checkpoint；固定 test 的 1 个样本完成 baseline 与 75% learned-utility 生成并严格满足预算。

尚未运行正式 120/30 样本标签生成、3-seed scorer 训练和固定 50 样本主实验。2026-10-17 检查时只有 GPU 0 空闲，2/5/6 仍有其他任务，因此没有启动多卡全量流程。smoke checkpoint 只由各 1 个样本训练/验证，不代表方法效果，正式实验前必须覆盖完整 split。

## 6. 下一步计划

GPU 资源合适后按以下顺序运行：

1. 多卡生成完整 train/validation utility label，并汇总 label 分布、失败数、耗时和显存；
2. 使用 3 个 seed 训练 scorer，只根据 validation 指标冻结 checkpoint；
3. 一次性运行固定 50 样本的 baseline、random、fixed、raw Qwen 和 learned utility 主比较；
4. 根据 oracle、validation 排名和下游结果区分标签、scorer 特征与 leave-one-out 交互问题；
5. 随后完成实验 003，并分别评估其独立方法、chunk 内辅助选择及 scorer 可选特征。
